# DO NOT install this file by hand. Run:
#
#     bash scripts/bootstrap_env.sh          # builds .venv and PROVES it works
#
# It pins the same versions listed below, installs the pieces pip cannot resolve on its
# own, and then refuses to finish unless a real CUDA kernel runs, cv2 works against the
# installed numpy, and auto_LiRPA imports. Every trap documented in this file is one it
# already handles.
#
# Python 3.12, CUDA 13.0, RTX-class GPU.
#
# torch / torchvision are installed from the PyTorch CUDA index, NOT plain PyPI:
#
#   pip install torch==2.13.0 torchvision \
#       --index-url https://download.pytorch.org/whl/cu130
#
# THE CUDA BUILD MUST MATCH THE CARD'S COMPUTE CAPABILITY. `torch 2.5.1+cu121` builds
# for sm_50..sm_90 and the lab desktop's RTX 5090 is sm_120: `torch.cuda.is_available()`
# returns True, `get_device_name()` answers correctly, and then EVERY kernel dies with
# "no kernel image is available for execution on the device". Check with
# `torch.cuda.get_arch_list()`, never with `is_available()`.
#
# The CARLA 0.9.16 client wheel installs separately. It does NOT pin Python to 3.10 --
# `$CARLA_ROOT/PythonAPI/carla/dist/` ships cp310, cp311 and cp312 wheels side by side,
# and the one matching your interpreter must be chosen explicitly. A bare glob picks
# cp310 first and pip rejects it as "not a supported wheel on this platform".
#
# ---------------------------------------------------------------------------
# auto_LiRPA -- install from UPSTREAM GIT, never from PyPI.
#
#   pip install --no-deps --ignore-requires-python \
#       git+https://github.com/Verified-Intelligence/auto_LiRPA.git
#
# Four traps, all hit for real:
#
#  1. PyPI `auto_LiRPA` is stuck at 0.3 and is years stale. Installing it DOWNGRADES
#     torch to 1.12.1, silently breaking CUDA in the environment, and then fails to
#     import anyway (it references numpy.lib.arraysetops, removed in modern numpy).
#  2. `--no-deps` is mandatory for the same reason: without it pip rewrites torch.
#  3. Upstream declares `requires-python ~=3.11`, which is why --ignore-requires-python
#     is needed. The constraint is conservative rather than a real code dependency --
#     verified by `scripts/verify_smoke.py`, which computed real bounds on a real
#     StudentNet and passed all three cross-checks. THAT SCRIPT IS NO LONGER IN THIS
#     REPO: it was pruned in commit cd01256 ("Prune to a minimal public artifact
#     repo"). It is still recoverable, and re-running it after a reinstall is still
#     the right move rather than trusting that the stack works:
#         git show cd01256^:scripts/verify_smoke.py > /tmp/verify_smoke.py
#         python /tmp/verify_smoke.py
#  4. `--no-deps` also means auto_LiRPA's OWN imports are not installed. Three are
#     needed at import time -- appdirs, tqdm, graphviz -- and without them
#     `import auto_LiRPA` dies with ModuleNotFoundError. Install them --no-deps too,
#     so pip still cannot rewrite torch:
#         pip install --no-deps appdirs tqdm graphviz
#
# Do NOT vendor auto_LiRPA, and do NOT use the SDP-CROWN fork. The fork's only addition
# is the SDP-CROWN ReLU relaxation, which requires an L2 ball and is vacuous on our
# low-rank sets. We touch only the public API: BoundedModule, BoundedTensor,
# PerturbationLpNorm. `verify_smoke.py` (see trap 3 for how to recover it) asserts the
# installed package carries no SDP-CROWN markers.
# ---------------------------------------------------------------------------
